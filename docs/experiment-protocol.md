# 빨래 접기 실험 프로토콜

이 문서는 로봇 모델이 정해지고 세부 구성과 policy는 미정인 상태의 시작안이다. **미정 항목을 확정하고 평가 규칙을 기록한 뒤** 비교 실험을 시작한다. 초기 목표는 같은 작업을 반복하고 실패 원인을 설명할 수 있는 실험 흐름을 만드는 것이다.

## 1. 작업 정의

| 항목 | 현재 상태 / 실험 전 결정할 내용 |
| --- | --- |
| 실행 환경 | 미정: 시뮬레이션 또는 실제 로봇 |
| 로봇 | 확정: ROBOTIS AI Worker FFW-SG2 |
| 장비 세부 구성 | 미정: 그리퍼·카메라·드라이버, 자유도, 제어 주기, 좌표계, 보정 방식 |
| 대상 의류 | 미정: 종류, 크기, 소재, 개별 물체 ID |
| 시작 상태 | 미정: 펼쳐짐·구겨짐 범위, 위치·방향 범위, 앞뒤 구분 |
| 목표 상태 | 미정: 접는 순서, 최종 모양·위치·방향 |
| 관측·행동 | 미정: 이미지/상태/언어 입력, 행동 표현과 실행 주기 |
| 종료 조건 | 미정: 성공 판정, 최대 시간·행동 수, 안전 중단 조건 |
| 학습 조건 | 미정: 시연 수, 추가 데이터, pretrained checkpoint, 연산 예산 |

처음에는 의류 한 종류와 접기 방식 하나로 범위를 제한한다. 예를 들어 직사각형 수건 한 장을 정해진 선을 따라 한 번 접는 작업을 후보로 삼을 수 있다. 이는 확정된 연구 범위가 아니다.

## 2. 비교 조건 고정

- 같은 평가 물체, 시작 상태 목록, 목표, 관측 정보, 종료 규칙과 평가자를 사용한다. 실물에서는 초기 상태 사진과 배치 지침으로 재설정하고, 가능한 오차를 기록한다.
- policy 실행 순서를 무작위화하거나 번갈아 배치해 시간 경과와 장비 상태 영향을 줄인다. 시작 상태 ID별로 결과를 짝지어 비교한다.
- 데이터, 학습 예산, 센서 입력을 맞추는 비교와 각 시스템의 권장 설정을 쓰는 비교를 구분한다. 조건이 다르면 차이를 표에 공개하고 policy 구조만의 효과로 해석하지 않는다.
- 사전학습 데이터·가중치의 출처와 확인 가능한 범위를 기록한다. 출처가 불명확한 데이터와 평가 물체의 중복 여부는 `unknown`으로 남긴다.
- 학습 가능한 policy는 가능하면 여러 학습 seed로 반복한다. 같은 checkpoint의 여러 실행은 독립적인 학습 반복으로 세지 않는다.

## 3. 데이터 분리와 평가 고정

1. 수집 전에 분리 기준을 정한다. 최소한 같은 시연 에피소드에서 나온 프레임과 재가공본은 모두 같은 split에 둔다.
2. 일반화 대상에 따라 물체 ID, 수집 세션, 작업자, 배경 중 필요한 단위를 묶어 train/validation/test를 나눈다. 새로운 의류에 대한 일반화를 주장하려면 test 물체 ID를 학습·검증과 분리한다.
3. 각 split의 에피소드·물체 ID와 파일 checksum을 manifest로 보관한다. 중복 파일뿐 아니라 같은 시연의 잘린 영상·증강본도 점검한다.
4. 정규화 통계는 train에서만 구한다. 모델 선택, 하이퍼파라미터, 성공 임계값 조정은 validation까지만 사용한다.
5. test 실행 전 checkpoint, 설정, 성공 기준, 시도 수, 제외 규칙을 고정한다. test 결과를 보고 수정한 모델은 탐색 결과로 표시하고, 최종 비교에는 새로운 holdout을 사용한다.

시연이 적어 엄격한 분리가 불가능하면 이를 기능 확인 실험으로 명시한다. 학습에 등장한 물체의 새 배치 결과와 처음 보는 물체의 결과는 별도로 집계한다.

## 4. 성공 판정

의류 종류와 접기 방식마다 아래 기준을 **실행 전에** 채운다. 모든 policy에 같은 기준을 적용하며, 영상에서 다시 판정할 수 있어야 한다.

| 기준 | 사전에 기록할 값 |
| --- | --- |
| 접기 완료 | 필요한 접기 횟수·순서와 확인 방식 |
| 형태 | 목표 윤곽, 겹침·모서리 정렬 오차의 허용치와 측정 단위 |
| 위치·방향 | 최종 위치·방향 허용 범위, 필요하지 않으면 해당 없음 |
| 유지 | 그리퍼를 놓은 뒤 목표 상태가 유지되어야 하는 시간 |
| 시간 제한 | 관측 시작부터 종료까지 최대 시간 |
| 자율 수행 | 시작 이후 사람이 물체·로봇·명령을 수정하지 않았음 |

필수 기준을 모두 만족한 경우만 `autonomous_success`로 센다. 수동 개입 후 완료한 결과는 별도로 기록하고 자율 성공에 포함하지 않는다. 안전 중단, 시간 초과, policy 오류도 실행이 시작된 시도의 실패에 포함한다.

장비 고장 등으로 평가가 무효가 되는 조건은 사전에 정한다. 원래 기록을 삭제하지 말고 무효 사유와 재시도 ID를 남긴다. 가능하면 policy 이름을 가린 영상으로 판정하고, 모호한 사례는 두 평가자의 판정과 불일치를 보관한다.

## 5. 시도별 기록

한 시도는 하나의 `trial_id`를 갖는다. 실행 시작부터 성공 또는 중단까지를 한 단위로 기록한다.

- **조건:** 실험 ID, 시각, policy·checkpoint, 학습/실행 seed, 물체·시작 상태 ID, split, 목표와 성공 기준 버전.
- **결과:** 각 성공 기준의 값, 최종 판정, 실패의 주된 원인과 보조 태그.
- **시간:** 최초 관측을 요청한 시점부터 종료 판정까지의 실제 경과 시간. 추론·대기·복구를 포함하며, 초기 배치·리셋 시간은 별도 기록한다.
- **개입:** 횟수, 시각, 유형, 이유. 자동 복구는 수동 개입과 구분해 기록한다.
- **관찰 자료:** 초기·최종 이미지, 전체 영상, 필요시 센서·행동 로그, 파일 경로와 checksum. 영상과 로그의 시간 기준을 맞춘다.
- **재현 정보:** Git commit, 미커밋 변경 사항, 전체 설정, 의존성 버전, 가중치 checksum, 하드웨어·펌웨어, 카메라 보정, 제어 주기, 연산 장치.

실패 태그의 초기 목록은 `perception`, `grasp_miss`, `slip`, `fold_alignment`, `entanglement`, `out_of_workspace`, `timeout`, `safety_stop`, `policy_error`, `hardware_error`, `other`로 둔다. 관찰만으로 원인을 확정할 수 없으면 `unknown`을 사용하고 추측을 사실로 기록하지 않는다.

## 6. 집계와 보고

- 전체 및 의류 종류별 자율 성공 수 / 유효한 전체 시도 수를 먼저 제시한다. 실패·무효·재시도 수와 제외 이유도 함께 공개한다.
- 성공률에는 표본 수와 적절한 불확실성 구간을 붙인다. 동일 물체나 학습 seed에서 반복된 시도 간 의존성을 고려한다.
- 시간은 전체 시도의 종료 시간과 성공한 시도의 완료 시간을 구분한다. 실패 시도를 뺀 평균만으로 속도를 비교하지 않는다.
- 개입이 발생한 시도 비율, 시도당 개입 횟수, 실패 유형 분포를 함께 보고한다.
- 대표 성공 영상뿐 아니라 실패 사례도 보관한다. 공개 저장소에는 재현에 필요한 코드·설정·작은 메타데이터를 넣고, 대용량 영상·데이터·가중치는 접근 방법과 버전을 기록한다. 공개 영상의 개인 식별 정보와 데이터·가중치의 배포 권한을 확인한다.

## 7. 최소 시작 실험

1. 장비와 의류 한 종류를 정하고, 수동 또는 간단한 scripted baseline으로 목표 동작이 가능한지 확인한다. 실물은 낮은 속도에서 작업 영역과 정지 동작을 확인한다.
2. 시작 상태 5개를 정해 사진·위치·방향을 기록하고, 성공 임계값과 제한 시간을 고정한다.
3. baseline과 첫 후보 policy를 각 시작 상태에서 2회씩 실행한다. 총 20회이며 실행 순서를 교차·무작위화한다. 학습이 필요하면 평가용 시도와 분리된 시연으로 준비한다.
4. 매 시도 로그와 영상을 남기고, 성공 판정 및 실패 유형을 다시 검토한다.
5. 이 결과는 파이프라인 확인용으로 보고한다. 확인된 문제를 수정한 뒤, 본 비교에서는 별도로 고정한 평가 세트·시도 수·여러 학습 seed를 사용한다.

이 20회는 통계적 우열을 보장하는 표본 수가 아니다. 본 비교의 시도 수는 관찰된 변동과 구분하려는 성능 차이를 바탕으로 사전에 정한다.
